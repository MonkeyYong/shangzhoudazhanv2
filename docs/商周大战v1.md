## 三、分层架构

项目采用**单文件内分四层 + 一条 AI 旁路**，用 `/* ==== */` 注释圈划分（共 12 个章节分隔点）。

```
codes/商周大战.html  (index.html)
│
├─ <style>                  视觉样式（CSS 变量 + 媒体查询）
├─ <body>
│   ├─ #board-wrap > canvas 棋盘（Canvas 2D）
│   └─ #panel              信息面板（DOM）
│
└─ <script> "use strict"     游戏逻辑（~2500 行 JS）
    │
    ├─ 数据层         L485–503    SIZE/COL_LETTERS/MARGIN/CELL/BOARD_PX、WHITE_PALACE/BLACK_PALACE
    │                             WHITE_HALF、PRESETS、SKINS、调色板常量
    │                             全局状态：pieces/turn/selected/legalMap/...
    │
    ├─ 开局配置       L504–544    buildLayout(key) → 3 档（14/22/34 子）
    │
    ├─ 皮肤系统       L545–812    paintSuJian / paintStar / paintShanShui / buildBgCache
    │                             loadSkin / saveSkin / applySkin / buildSkinRow
    │
    ├─ 规则层         L910–1448   通用规则：reachableCells / legalMoves / moveLog / notation
    │                             武王状态：recomputeKingStates / isImprisoned / activeUnlockCheck
    │                             分身/暴走：cloneOfferCheck / berserkCheck
    │                             胜负/平局：checkWinLoss / hasAnyMove / positionHash
    │                             行动执行：doMove / settleMove / finishTurn
    │                             悔棋/复盘：snapshot / restoreSnapshot / undo / redo / replayGoto
    │
    ├─ AI 引擎        L1449–2060  独立模拟器 sim*（不碰全局状态）
    │                             ├─ sim 数据：Int16Array(361) 占用表 + 棋子克隆
    │                             ├─ sim 规则：simAt / simGenMoves / simHasReach / simCanAttack
    │                             │             simKingOf / simBerserkCheck / simCloneOffered
    │                             │             simDoMove / simSettle / simWinner / simHasAnyMove
    │                             ├─ 评估函数：simEval（王价值 + 机动 + 围王 + 解锁梯度）
    │                             ├─ Zobrist 哈希：initZobrist / simHash（mulberry32 固定种子）
    │                             ├─ 置换表：TT_SIZE = 1<<18（≈ 8 MB Int32/Uint8 混合）
    │                             ├─ 搜索：qsearch / negamax（α-β + 迭代加深 + deadline）
    │                             └─ 选着：aiChooseMove（timeLimitMs 超时保留上一层）
    │
    ├─ 渲染层         L2062–2518  fitCanvas（dpr 适配）/ drawBoard / drawPalaceDecor /
    │                             drawHighlights / drawPieces / renderScoresheet
    │                             hoverRAF / 离屏缓存 _bgCache
    │
    ├─ 交互层         L2519–2874  canvas 事件：click / mousemove / mouseleave
    │                             按钮：newGame / undo / redo / preset / opponent / level
    │                             摆子：enterSetup / clearSetup / startFromSetup / validateSetup
    │                             棋谱：exportRecord / importRecord / startReplay / exitReplay
    │                             复盘导航：replayGoto / enterStudy / exitStudy
    │                             自定义下拉：makeDropdown
    │
    └─ 启动           L3006–3019  loadCustomLayout → initPieces → buildSkinRow
                                  → loadSkin → fitCanvas → applySkin → renderScoresheet
```

**架构关键设计：**
- **数据层只存状态，不碰 DOM**（设计文档明文约束）
- **规则层非纯函数**：直接读写全局 `pieces`/`turn`/`sideLostClone` 等
- **AI 引擎零侵入**：自带 `sim*` 翻版（约 200 行），通过 `Int16Array(361)` 占用表实现 O(1) 查子，不依赖全局状态（异常安全 + 性能）
- **后退栈可见**：`undoStack`/`redoStack`/`moveLog`/`positionCounts`（循环局面检测）

## 五、潜在隐患与优化点

### 5.1 安全与健壮性

| # | 位置 | 隐患 | 建议 |
|---|---|---|---|
| 1 | `index.html:792,800,1331` | `innerHTML` 用字符串拼接（皮肤色块、棋谱条目） | 当前数据均为代码内常量，**当前无 XSS 风险**；但若未来允许用户自定义 HTML 片段，建议改 `textContent` + 创建子节点 |
| 2 | `index.html:778,864,874,2005,2638,2797` | `try/catch` 多处**静默吞错**（仅 `saveSkin` 有 注释 "隐私模式等写失败时静默忽略"） | 至少开发模式应 `console.error(e)` 便于排查 |
| 3 | 全文 | **无 `console.error` / `console.warn`**（仅 1 处 `console.log` 输出 AI 决策信息） | 调试极不友好；建议对捕获的异常统一用 `console.error` 上报 |
| 4 | `index.html:483` | `"use strict"` 仅在脚本顶部 | 整段脚本共用严格模式，但 `<style>` 与 `<script>` 内联块未隔离（HTML 解析不会出问题，但未来拆模块需注意） |
| 5 | 全文 | 无 CSP、无 SRI、无 iframe sandbox | 部署到 GitHub Pages 建议 `meta http-equiv="Content-Security-Policy"` 至少限制 `script-src 'self' 'unsafe-inline'`（本项目脚本内联，无法避免 `'unsafe-inline'`） |
| 6 | `index.html:2797` `importRecord(e)` | 接受 `FileReader` 读取的 JSON，但**未做 schema 校验** | 仅 `Array.isArray(d) && d.length===4` 过滤；类型字段若被攻击者改为未知值，可能进入 `sim*` 触发异常 |
| 7 | `index.html:2733` `syncPresetDropdown` | `window.syncPresetDropdown = ...` 暴露到全局 | 调试便利，但可能被外部脚本劫持；建议改为闭包或显式命名空间 |

### 5.2 性能与可维护性

| # | 位置 | 问题 | 优化建议 |
|---|---|---|---|
| 8 | `index.html:858,992–994,1083,1117` | 多处 `pieces.filter(p => ...)` / `pieces.find(p => ...)`（O(P) 线性扫描） | 规则层频繁调用（评估、选着）；建议维护 `byId`/`bySide`/`byType` 索引 Map |

## 六、亮点

- **零依赖、零构建**：双击即玩，符合设计文档"小白友好"的初衷
- **AI 引擎独立模拟器**：sim* 与全局规则解耦，搜索引擎性能与异常安全兼顾
- **Zobrist 哈希 + 置换表 + killer 启发**：完整的现代博弈搜索骨架
- **迭代加深 + 时间预算**：AI 永不让玩家等"永不返回"
- **离屏缓存（`_bgCache`）**：复杂皮肤无重复重绘
- **DPR 适配**：高分屏清晰，移动端通过媒体查询切换
- **3 档开局 + 自由摆子 + 棋谱导入导出 + 复盘 + 研习模式**：功能完整
- **设计文档先行**：`docs/设计文档.md` + `docs/AI对战设计文档.md` 列出所有硬约束（如"修改规则必同步 sim* "）
- **`.claude/ai-smoke-test.js`** 主动验证 `simGenMoves` 与全局 `legalMoves` 的一致性——罕见但严谨的做法
